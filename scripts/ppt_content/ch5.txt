#SECTION 讲次 5-1 · Multi-Agent 模式与边界
#PAGE 先问要不要 Multi-Agent
• 不是所有任务都需要团队作战
• 单 Agent 能做就别上多 Agent
• 每多一个 Agent 多一份成本与风险
>>复杂度是成本,不是勋章
#PAGE 单 Agent 适用场景
• 目标明确、步骤较短
• 上下文集中,工具链简单
• 例:单文件修复/单问题问答
>>多数日常任务是单 Agent
#GRID 单/多 Agent 决策卡|单:目标明确/步骤短/上下文集中;多:多视角/大规模/多源聚合;判据:一个窗口装得下吗;成本:多 Agent = 多倍 Token|cols=2|先问要不要,再问怎么做

#PAGE Multi-Agent 适用场景
• 多视角:代码审查/研究分析
• 大规模:安全扫描/性能诊断
• 报告生成:多源信息聚合
>>一个窗口装不下的任务
#PAGE Supervisor 模式
• 主控:拆解/调度/收集/决策
• 工人:只管自己的子任务
• 类比:技术经理与团队
>>平台 SupervisorAgent 已实现
#ARCH Supervisor 协作拓扑|主控 Agent:任务拆解,调度,决策;并行 Worker:Architecture,Test,Security,Performance;支撑:结果聚合,冲突仲裁,证据保留;约束:超时隔离,Token 预算|flow=拆解,并行执行,聚合仲裁|asyncio.gather 实现十万级并发原语同款

#PAGE Planner/Executor 模式
• Planner 出计划,Executor 干活
• 适合长程任务解耦
• 计划修订回流 Planner

#PAGE Reviewer 模式
• 独立审查 Agent 复核结果
